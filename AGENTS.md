# AGENTS.md

Notes for coding agents working on this repo. Read [README.md](README.md) first for what the demo is.

## Setup

- There is no build step, no package.json and nothing to install. Plain HTML, CSS and ES modules.
- Serve the root with any static server (`npx serve .` or `python3 -m http.server`). ES modules don't load from `file://`.
- GSAP (with Flip and ScrollTrigger) and Lenis are vendored in `js/` and loaded as classic scripts before the module, so `gsap`, `Flip`, `ScrollTrigger` and `Lenis` are globals. Don't import them.
- The analytics and ad scripts are commented out in every page. They're added on the live server only; leave them commented out here.
- There are no automated tests. Check a change in a browser: scroll through every gallery on both pages at desktop and phone width, resize the window in the middle of a gallery, turn on reduced motion, and look at the console.

## How a gallery works

Every gallery is two layouts in CSS and one Flip animation between them, scrubbed by scroll while the gallery is pinned.

```html
<div class="gallery-wrap">
	<div class="gallery gallery--row" id="gallery-1">
		<div class="gallery__item" style="background-image:url(img/6.webp)"></div>
		…
		<div class="caption">…</div>
	</div>
</div>
```

- **The start layout** is `.gallery--<layout>` in `css/base.css`. **The end layout** is the same gallery with `.gallery--switch` added (`.gallery--switch.gallery--<layout> …`). Design both in CSS first; the JS only measures them.
- `triggerFlipOnScroll` adds `.gallery--switch`, records the items and the caption with `Flip.getState` (`props: 'filter, opacity'`, so those two animate as well), removes the class again, then calls `Flip.to` with a scrubbed ScrollTrigger that pins the `.gallery-wrap`. The class never stays on, except with reduced motion (below).
- Only the items and the caption are animated. A switch rule on anything else (like `.gallery--switch.gallery--grid .caption p`) only changes what gets measured.
- `scroll()` goes through the `galleries` list, which holds every page's galleries, and skips the ones that aren't on the page.
- The defaults are pinned from `'center center'` for `'+=300%'`, `scale: true`, `simple: true`, `props: 'filter, opacity'`, no stagger and a linear ease (`'none'`). `flip.props` lists the CSS properties Flip records and animates besides the layout (the slit-scan adds the background's size and position). Each gallery overrides them in the `galleries` list in `scroll()`, one group at a time (`flip`, `scrollTrigger`, `stagger`, `ease`); the other defaults of a group stay. With `scale: false`, Flip animates `width` and `height` instead of scale.
- A layout that places each item by its number reads `--i` from the item's inline style, next to its picture (the sunflower, whose end layout is computed in CSS with `cos()`, `sin()` and `sqrt()`). Absolutely placed end layouts set `grid-area: auto` on grid items, or the grid cell becomes their containing block. A caption whose box would change size between the two layouts gets the same box in both (absolute, `inset: 0`), or Flip scales its text unevenly.
- **3D layouts.** Flip only records 2D (position, size, 2D rotation and scale), so a gallery with a 3D start gets its own function, set with `animate` in the `galleries` list. The carousel uses one for its 3D part and still ends with a Flip switch. `triggerUnrollOnScroll` (the carousel) leaves the pictures in their CSS layout (the row, or the column on phones), measures where each one lies, and on every update places them on a ring whose bend goes from a closed circle to flat: each picture at `sin(angle) / bend` along the row and `(cos(angle) - 1) / bend` in depth, turned by its angle, its `--light` (read by the CSS `filter`) dimming towards the back. Its trigger is the wrapper, since the gallery itself starts tilted and scaled. With reduced motion nothing runs and the CSS layout shows as it is.
- `.gallery__item-inner` elements (gallery 2) also zoom from 2 to 1. That tween has its own ScrollTrigger with the gallery's start and end: Flip puts the `scrollTrigger` on a tween inside the timeline it returns, so that timeline isn't scrubbed, and a tween added to it needs its own trigger.
- **Resizing.** Flip records both layouts in pixels, so `initLayoutAnimations` builds every gallery again after the window changes size (only the width counts on touch screens, where the toolbar changes the height). Reverting a `Flip.to` leaves its end state inline, so it first puts back the inline styles the items and captions started with. Keep the pictures in those inline styles and nothing else.
- **Reduced motion.** `gsap.matchMedia()` sets everything up only for `(prefers-reduced-motion: no-preference)`. With `reduce`, every gallery gets `.gallery--switch` and stays still, there's no Lenis and no pinning, and the page scrolls natively. The end layouts are where the captions can be read.
- **Start-up.** The page waits for every picture (on `.gallery__item` and `.gallery__item-inner`) and for the fonts before anything is measured, then removes `loading` from the body.

## Adding a layout

1. Layouts 02 follows `index.html`'s order of galleries and text sections, with its own pictures and copy (galleries 3 and 7 reuse page 1's pictures). A gallery can also be an extra example after a slot, using that slot's pictures, like the pyramid after the carousel.
2. Give it a named id and a `gallery--<name>` class, write its start and end layouts in `css/base.css`, and add `{ id: '#gallery-<name>', options }` to the `galleries` list in `js/index.js`, under its page. A layout Flip can't record (3D) gets its own function, passed as `animate`.
3. A new layouts page (`index3.html`…) starts as a copy of `index2.html` with its own `<title>`, description, canonical, `og:url` and JSON-LD `url`. Add it to the `.frame__demos` nav on **every** page; the current page's entry is a `<span class="frame__demo frame__demo--current" aria-current="page">`, not a link.

## Style

- Tabs in `js/index.js` and `css/base.css`, four spaces in `js/utils.js`. Single quotes and semicolons. Follow what's in the file.
- Functions are `const name = () => {}`, and conditions are written `if ( condition )`.
- A short comment above almost every step, saying what it does ("// Select elements within the gallery that will be animated").
- Flat CSS with BEM-style names (`gallery__item`, `gallery--row`), the end state as the `gallery--switch` modifier, sizes mostly in `vw` and `vh`.
- No dependencies and no build tooling unless asked.

## Ask before changing

- The `<title>`, meta description, keywords and social tags, the `frame__title` heading, the frame's links and tags.
- The credits (in the README and the page's Photo credits section), the page's text and the pictures.
- The closing "More demos in the Creative Hub" button (`.cta__link`), the same on every page, and the link under it to the other layouts page (`.cta__next`).
- The layouts and options of the nine galleries in `index.html`, which are the author's own.
